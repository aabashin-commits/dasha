# Keyframe — сайт видеопродакшн-студии

Статический сайт из обычных HTML-файлов. **Сборки нет.** Что лежит в папке — то и отдаётся браузеру.

Как править: `docs/how-to-edit.md`. Визуальные решения и их обоснования: `docs/design-direction.md`.

---

## Стек

HTML5 + CSS3 + vanilla JS. PHP 8.1+ только в `api/lead.php`.

**Не использовать:** любые фреймворки, библиотеки, препроцессоры, сборщики и пакетные менеджеры. В проекте нет `package.json` и не должно появиться. Если задача выглядит так, будто требует сборку, — сначала обсудить.

Никаких ES-модулей: `assets/script.js` подключается как обычный скрипт, чтобы страница работала и с сервера, и при открытии с диска.

## Главное следствие отказа от сборки

**Шапка, подвал и форма заявки продублированы на всех 22 страницах.** Правка любого из них — правка во всех файлах. Перед изменением сквозного элемента:

```
grep -rl "что меняем" --include=*.html .
```

Пропустить файл — обычная ошибка здесь. После правки перепроверить тем же grep, что старого варианта не осталось.

## Дизайн-система

Все значения — переменные в блоке `:root` в начале `assets/style.css`. В остальных секциях использовать только `var()`.

**Запрещено:** хардкод цветов (`#fff`, `rgb()`, `rgba()`), размеры шрифта в px, отступы вне шкалы `--sp-*`, `!important` (единственное исключение — блок `prefers-reduced-motion`), `z-index` вне шкалы токенов.

**Акцентный лайм `--lime`** занимает не более ~5% площади экрана — это сигнал, а не фон.

- Разрешён: первичные кнопки, кольцо фокуса, плейхед и активный маркер спайна, номера этапов процесса, активный пункт фильтра, кнопка Play.
- Запрещён: заливки секций, длинный текст, фон карточек.
- Текст поверх лайма — всегда `--lime-ink`. На светлом фоне лайм не использовать: контраст 1.2:1.
- Нумерации 01–04 на карточках направлений нет: они параллельны, а не последовательны. Номера только в блоке процесса.

**Контраст проверен расчётом.** `--ink-3` поднят до `#7A817B` (4.9:1), потому что прежнее значение давало 2.9:1 и проваливало AA. `--line-ui` отделён от `--line-lit` ради границ интерактивных элементов (3.2:1 по WCAG 1.4.11). Менять эти два токена без пересчёта контраста нельзя.

Анимируем только `transform` и `opacity`. Блок `@media (prefers-reduced-motion: reduce)` обязателен.

## Правила кода

- CSS: секции с заголовками `/* --- ИМЯ --- */`, классы по BEM (`.work-card__title`).
- JS: один файл, блоки по зонам ответственности, каждый со своей функцией `init*` и молча выходит, если своих элементов на странице нет.
- Комментарии объясняют «почему», а не «что».

**Ловушки, на которые уже наступали:**

- **Появление секций скрывается только под классом `.js`.** Правило `.reveal{opacity:0}` без этого гейта оставляет пустую страницу при отказе JS. Инлайн-скрипт в начале `<body>` ставит класс — не удалять.
- **`aspect-ratio` не работает на inline-элементе.** Обёртке медиа внутри `<a>` нужен `display:block`, иначе высота нулевая.
- **Имена классов проверять на коллизии.** `.w-b` как размещение в сетке и как подпись карточки — разные вещи с одним именем. Классы раскладки идут с префиксом `.pos-*`.
- **`querySelector` находит первое совпадение, а не нужное.** Подпись под кадром героя не обновлялась, потому что тот же `data`-атрибут висел на `<img>` выше по документу. Атрибуты подписи и медиа должны различаться.
- **Ханипот не уводить за `left:-9999px`** — это растягивает область прокрутки и даёт горизонтальный скролл на каждой странице с формой. Использовать клип-паттерн.
- **У заголовков обязателен `overflow-wrap: break-word`.** Unbounded шире обычного гротеска, и длинное русское слово переполняет вьюпорт на 390px.

## SEO — проверять на каждой странице

Ровно один `<h1>`. Уровни заголовков не пропускаются: если карточки набраны `h3`, между ними и `h1` должен быть `h2` — при необходимости скрытый через `.visually-hidden`.

Обязательны: `title` (≤60), `description` (≤160), `canonical`, полный Open Graph с `og:image` 1200×630, блок JSON-LD.

Изображения: `<picture>` с цепочкой AVIF → WebP → JPG, обязательные `width` и `height`, осмысленный `alt`.

При добавлении страницы — дописать её в `sitemap.xml` руками.

## Безопасность

Секреты — токен Telegram-бота, `chat_id`, доступы SMTP, `CRM_WEBHOOK_URL` — только в `api/config.php`, который в `.gitignore` и закрыт правилом `.htaccess`. Никогда в клиентском коде и никогда в репозитории.

`lead.php` обязан выполнять все шаги: проверка Origin, honeypot, временная метка, rate limit, валидация и санитизация каждого поля. Валидация в `script.js` дублирует серверную, но не заменяет её.

---

## Доступность

Контраст ≥4.5:1 для текста и ≥3:1 для интерактивных элементов. Видимый `:focus-visible`. Полная навигация с клавиатуры. `aria-expanded` на раскрывающихся элементах, `aria-live` на результате формы, фокус-ловушки в мобильном меню и лайтбоксе. Тач-цели ≥44×44px, кроме инлайновых ссылок в тексте.

## Проверка вёрстки: как не жечь ресурсы

### Один сервер и одна вкладка на всю сессию

Сервер поднимается один раз (`python3 -m http.server 4321`) и живёт до конца работы. `browser_navigate` вызывается один раз, дальше вкладка переиспользуется. **Никогда не вызывать `browser_close` между проверками.**

### Сначала дешёвые проверки, браузер — последним

1. `grep` по HTML: количество `<h1>`, наличие `og:image` и `canonical`, пустые `alt`.
2. `grep` по `assets/style.css`: хардкод цветов (`#`, `rgb(`, `rgba(`), размеры шрифта в `px`, `!important` вне `prefers-reduced-motion`.
3. `node --check assets/script.js` — синтаксис.
4. И только теперь браузер — для пропорций, ритма, наложений, поведения при hover.

### Свип по всем страницам и ширинам одним вызовом

Один `browser_evaluate` с невидимым iframe вместо десятков навигаций:

```js
const frame = document.createElement('iframe');
frame.style.cssText = 'position:fixed;left:-3000px;top:0;height:900px;border:0';
document.body.append(frame);
for (const w of [360, 768, 1024, 1440, 1920]) {
  frame.style.width = w + 'px';
  for (const p of pages) {
    frame.src = p;
    await new Promise(r => { frame.onload = r; });
    const d = frame.contentDocument;
    if (d.documentElement.scrollWidth > frame.contentWindow.innerWidth + 1) { /* нашли */ }
  }
}
```

Тем же приёмом проверяются `h1`, длина `title`, наличие `og:image` — через `fetch` + `DOMParser`, вообще без рендера.

**Источник переполнения ищется так** (`getBoundingClientRect().right` его часто не видит):

```js
[...document.querySelectorAll('*')]
  .filter(el => el.scrollWidth > el.clientWidth + 1 && el.clientWidth > 0)
```

### Скриншоты: два обязательных шага

1. **`loading="lazy"`** — картинки ниже первого экрана не грузятся, карточки выходят пустыми. Перед снимком: `document.images.forEach(i => i.loading = 'eager')` и дождаться загрузки.
2. **Масштаб** — страница на 10 000px ужимается в пять раз, и тёмные кадры пропадают вовсе. Тёмную вёрстку смотреть скриншотом вьюпорта после `scrollIntoView()`, не миниатюрой всей страницы.

Плюс `.reveal` — элементы скрыты, пока не сработал IntersectionObserver; при съёмке проставить `.reveal--in` вручную.

### `browser_snapshot` дешевле скриншота

Вопрос про структуру, порядок элементов, семантику, `aria` — это `browser_snapshot`, он текстовый. Скриншот только для по-настоящему визуальных вопросов.
