# ТЗ: сайт видеопродакшн-студии Keyframe

**Дата:** 2026-08-01
**Статус:** утверждено заказчиком

---

## 0. Контекст и цель

Исходное ТЗ описывало лендинг, но содержало верную рекомендацию: строить не лендинг, а основу полноценного сайта студии, где каждая услуга и каждый кейс живут на собственной странице.

Это решение принято. Оно даёт три вещи, которых лендинг не даёт:

1. **SEO-охват по направлениям.** «Съёмка Reels» и «документальный фильм» — разные поисковые запросы, разные посадочные страницы.
2. **Посадочные под рекламу.** Reels ≠ Documentary: разная аудитория, разный чек, разные креативы. Вести трафик на один лендинг — терять конверсию.
3. **Рост портфолио без переделки сайта.** Новый кейс добавляется как данные, а не как вёрстка.

Проект стартует с нуля. Реального контента нет — верстаем на заглушках.

### Зафиксированные решения

| Вопрос | Решение |
|---|---|
| Хостинг и формы | РФ-хостинг (Beget/Timeweb) + PHP-эндпоинт → Telegram Bot API + email |
| Управление контентом | JSON-файлы в репозитории |
| Сборка | Node-генератор статики + Vite |
| Языки | Только RU, структура готова к расширению |
| Видео | Гибрид: свои MP4-лупы для превью + VK Video/Rutube для полных роликов |
| Услуги | 4 из ТЗ как заглушки, список меняется через JSON |
| Разделы | Блог, цены «от X ₽», О студии + команда, отзывы + логотипы клиентов |
| Визуал | Сдержанно-тёмный, кислотный лайм точечными акцентами |

### Главный архитектурный принцип

Контент отделён от разметки. Билд-скрипт читает JSON и генерирует статические HTML со всеми мета-тегами и микроразметкой. Добавление кейса = добавление объекта в `works.json` + сборка.

Клиентский рендер контента сознательно отвергнут: Яндекс плохо индексирует JS-контент, а Open Graph при шаринге кейса в Telegram не сработает вовсе.

**Разрешено:** HTML5, CSS3 (нативная вложенность, `@layer`, custom properties), vanilla JS (ES-модули), Node.js на этапе сборки, PHP 8.1+ для обработки формы.

**Запрещено:** React/Vue/Svelte, jQuery, Bootstrap/Tailwind, CSS-препроцессоры, любые runtime-зависимости в браузере.

**Допустимые dev-зависимости:** `vite`, `terser`, `sharp`, `html-minifier-terser`.

Результат сборки — статические HTML/CSS/JS плюс один PHP-файл.

## 4. Билд-система

### 4.1 Мини-шаблонизатор (`scripts/lib/template.js`)

Собственный, ~120 строк, без зависимостей.

| Конструкция | Назначение |
|---|---|
| `{{ var }}` | подстановка с HTML-экранированием |
| `{{{ var }}}` | подстановка без экранирования (только доверенный HTML) |
| `{{#if cond}}…{{else}}…{{/if}}` | условие |
| `{{#each items}}…{{/each}}` | цикл; внутри `this`, `@index`, `@first`, `@last` |
| `{{> partial-name }}` | вставка partial |
| `{{ var \| filter }}` | фильтры `money`, `date`, `truncate`, `plural` |

Разрешение путей вида `a.b.c`. **Неизвестная переменная → ошибка сборки, а не пустая строка.** Это ловит опечатки в JSON до прода.

### 4.2 `scripts/build.js`

1. Читает и валидирует все `content/*.json`.
2. Строит список страниц: статические (главная, о студии, контакты, privacy, 404) + динамические (по объекту на каждый элемент `services`, `works`, `journal`).
3. Рендерит каждую через `_layout.html` + шаблон страницы.
4. Собирает `<head>`: title, description, canonical, OG, Twitter, JSON-LD (раздел 8).
5. Минифицирует HTML, пишет в `dist/<path>/index.html`.
6. Генерирует `sitemap.xml`, копирует `robots.txt`.
7. Vite собирает CSS/JS с хешами в именах, критический CSS инлайнится в `<head>`.
8. Копирует `public/` в `dist/`.

### 4.3 `scripts/validate-content.js`

Запускается перед каждой сборкой. **Падает с внятной ошибкой** (файл, индекс объекта, поле), если:

- отсутствует обязательное поле;
- слаг не уникален или не соответствует `^[a-z0-9-]+$`;
- `service` в кейсе не найден среди слагов услуг;
- файл медиа, указанный в JSON, отсутствует на диске;
- `seo.title` длиннее 60 символов, `seo.description` — длиннее 160;
- у изображения нет `alt`.

Это техническая гарантия требования ТЗ «добавлять проекты без изменения структуры»: заказчик не может незаметно сломать сайт.

### 4.4 Команды

```
npm run dev        # Vite dev-сервер, watch по content/ и templates/
npm run build      # валидация → генерация → минификация → dist/
npm run preview    # локальный просмотр dist/
npm run validate   # только проверка контента
npm run images     # оптимизация public/media → WebP + AVIF
```

## 6. Дизайн-система

Референс — `dinerodev.com`: крупная типографика, много воздуха, карточные сетки. Тональность собственная: тёмная база с кислотным лаймом.

### 6.1 Цвет (`src/styles/tokens.css`)

```css
--bg-base:        #0A0A0B;   /* фон страницы, тёплый чёрный */
--bg-elevated:    #121214;   /* карточки */
--bg-inset:       #1A1A1D;   /* поля ввода */
--line:           #26262B;
--line-strong:    #3A3A42;

--text-primary:   #F2F2F0;
--text-secondary: #9A9A96;
--text-muted:     #5E5E5C;

--accent:         #C6F432;   /* кислотный лайм — сигнатура бренда */
--accent-hover:   #D6FF52;
--accent-dim:     rgba(198, 244, 50, 0.12);
--accent-ink:     #0A0A0B;   /* текст ПОВЕРХ лайма — только тёмный */

--danger:         #FF5C4D;
--success:        #C6F432;
```

**Правила использования акцента — обязательны:**

- Лайм занимает не более ~5% площади экрана. Он сигнал, а не фон.
- Разрешён: первичные кнопки, кольцо фокуса, номера услуг, активный пункт фильтра, кнопка Play, крупные цифры, подчёркивание ссылки на hover.
- Запрещён: заливки секций, длинный текст, фон карточек.
- Текст поверх лайма — всегда `--accent-ink`. На светлом фоне лайм не использовать: контраст 1.2:1.
- Проверено: `--accent` на `--bg-base` ≈ 15:1, `--text-secondary` на `--bg-base` ≈ 6.5:1 — оба проходят WCAG AA.

Главный герой страницы — видео клиента, а не интерфейс. Отсюда сдержанность.

### 6.2 Типографика

- Заголовки: **Unbounded** — геометричный гротеск с характером.
- Текст: **Onest** — нейтральный, хорошая кириллица.
- Технические подписи, цифры, таймкоды: **JetBrains Mono**.
- **Кириллицу всех трёх гарнитур проверить на этапе 2, до вёрстки страниц.** Если начертаний не хватит — фолбэк: **Manrope** для заголовков, **Inter** для текста.
- Только `.woff2`, локально в `/public/fonts`, подмножество `latin,cyrillic`, `font-display: swap`, `<link rel="preload">` для основного начертания.
- Максимум 4 начертания: Unbounded 500/700, Onest 400/600.

```css
--fs-display: clamp(3rem, 8vw, 7.5rem);      /* line-height .92, ls -.03em */
--fs-h1:      clamp(2.5rem, 5vw, 4.5rem);    /* line-height .98, ls -.02em */
--fs-h2:      clamp(2rem, 3.5vw, 3.25rem);
--fs-h3:      clamp(1.375rem, 2vw, 1.75rem);
--fs-body-lg: clamp(1.0625rem, 1.3vw, 1.25rem);
--fs-body:    1rem;
--fs-small:   0.875rem;
--fs-caption: 0.75rem;                        /* моно, uppercase, ls .08em */
```

### 6.3 Пространство и сетка

- Шкала отступов на базе 4px: `--sp-1: 4px` … `--sp-16: 128px`.
- Контейнер: `max-width: 1440px`, боковой padding `clamp(20px, 5vw, 80px)`.
- Сетка: 12 колонок desktop / 8 tablet / 4 mobile, gap `clamp(16px, 2vw, 32px)`.
- Вертикальный ритм секций: `clamp(80px, 10vw, 160px)`.
- Радиусы: `--r-sm: 4px`, `--r-md: 12px`, `--r-lg: 20px`, `--r-pill: 999px`.
- Брейкпоинты: 480 / 768 / 1024 / 1440. Разработка mobile-first.

### 6.4 Движение

- Анимируем только `transform` и `opacity`.
- Easing: `--ease-out: cubic-bezier(.16, 1, .3, 1)` для появлений, `--ease: cubic-bezier(.4, 0, .2, 1)` для интерфейсных.
- Длительности: `--t-fast: 180ms`, `--t: 320ms`, `--t-slow: 700ms`.
- Появление секций: `opacity 0→1` + `translateY(24px→0)`, порог IntersectionObserver 0.15, срабатывает один раз.
- Обязательно в `base.css`:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

- Скролл-джекинг, кастомные курсоры, параллакс на мобильных — не применять.

## 7. Компоненты и страницы

### 7.1 Ключевые компоненты

**Header** — sticky. При скролле вниз уезжает, вверх — возвращается (через `transform`, не пересчёт `position`). Логотип слева, меню по центру, телефон и кнопка «Обсудить проект» справа. Мобильный — фуллскрин-оверлей с `aria-expanded`, фокус-ловушкой и блокировкой скролла body.

**WorkCard** — постер 16:9. На desktop при hover, на mobile при попадании во вьюпорт запускается `preview.mp4` (muted, loop, playsinline, `preload="none"`). Оверлей: название, направление, год. На hover — лаймовая линия снизу и `scale(1.02)` изображения. Вся карточка — одна ссылка, без вложенных `<a>`.

**ServiceCard** — глиф соотношения сторон, вычерченный в истинной пропорции (9:16 — вертикальный прямоугольник, 2.39:1 — широкая полоса), рядом диапазон хронометража; название `<h3>`, описание, «от 45 000 ₽», стрелка. Hover: рамка глифа `--ink-3` → `--accent`.

Нумерации `01`–`04` на карточках услуг **нет**: четыре направления параллельны, а не последовательны, и номер сообщал бы несуществующий порядок. Формат и длительность — то, что клиент действительно сравнивает. Нумерация остаётся только в блоке «Как мы работаем», где последовательность настоящая.

**VideoFacade** — постер + лаймовая кнопка Play. Iframe VK/Rutube подставляется только по клику. Без этого один embed съедает ~1 МБ и портит LCP.

**LeadForm** — поля: имя, способ связи (radio: Telegram / Телефон / Email), контакт, направление (`<select>` из `services.json`), сообщение, чекбокс согласия со ссылкой на `/privacy/`. Honeypot скрывается через CSS-позиционирование, не через `display:none`. Состояния: idle / sending / success / error. Ошибки инлайн под полем, `aria-invalid`, результат в `aria-live="polite"`.

**Прочие:** Accordion (на `<details>` + JS для анимации), Marquee (одна бегущая строка направлений, останавливается при `prefers-reduced-motion`), LogoWall (грейскейл → цвет на hover), Testimonial, StatBlock, Lightbox (клавиатура + свайп), Breadcrumbs, Toast, CookieBanner.

### 7.2 Главная

1. **Hero** — display-заголовок, подзаголовок, две CTA («Обсудить проект» лаймом и «Смотреть работы» контурная) и **кадровое полотно вместо автоплей-шоурила**: один остановленный кадр, раз в 4,2 секунды жёсткая склейка на следующий, без кроссфейда. Слаглайн и таймкод обновляются вместе с кадром. Обоснование и откат — `docs/design-direction.md`. Пять статичных изображений вместо видеофайла: LCP становится картинкой, что прямо работает на цель Lighthouse ≥90.
2. **Направления** — 4 ServiceCard со ссылками на страницы услуг.
3. **Избранные работы** — 6 карточек с `featured: true`, ссылка «Все работы».
4. **Marquee** — бегущая строка направлений.
5. **Как мы работаем** — 4 шага с крупной нумерацией.
6. **Цифры** — 3–4 StatBlock (проектов, лет, часов материала).
7. **Отзывы + логотипы клиентов.**
8. **Журнал** — 3 последние статьи.
9. **FAQ** — 6 аккордеонов.
10. **CTA-блок** — форма заявки.

### 7.3 Страница услуги

Hero с видео направления → задача, которую услуга решает → что входит (`features`) → процесс по шагам → примеры работ этого направления (`works`, отфильтрованные по `service`) → цена «от» и что влияет на стоимость → FAQ услуги → CTA. `<h1>` = название услуги.

### 7.4 Портфолио и кейс

**Список.** Фильтр по направлению — кнопки-пилюли, активная лаймом. Фильтрация на клиенте, состояние пишется в `?service=reels` через `history.replaceState`, при загрузке читается из URL. **Все карточки присутствуют в HTML** — фильтр только скрывает, поэтому индексация не страдает.

Сетка **неоднородная**: каждая карточка живёт в истинном соотношении сторон своей работы — Reels вертикальные 9:16, документальные широкие 2.39:1. Приведение всех работ к единому 16:9 стирает разницу между форматами, которая здесь является содержанием. Раскладка на 12 колонках задаётся явно (вертикали занимают две строки, горизонтали складываются рядом), чтобы правый край сетки не рвался. Ниже 760px — одна колонка.

**Кейс.** Hero с постером и кнопкой Play (VideoFacade) → мета-строка (клиент, год, направление, локация) → описание → галерея с лайтбоксом → результаты в цифрах → команда проекта → следующий кейс → CTA. Хлебные крошки. `<h1>` = название кейса.

### 7.5 Остальные страницы

- **О студии** — философия, процесс, команда из `team.json`, оборудование, CTA.
- **Журнал** — список карточек, статическая пагинация по 9. Статья: типографика чтения, максимум ~68 символов в строке, шаринг, похожие статьи.
- **Контакты** — реквизиты, прямые ссылки (`tel:`, `mailto:`, `t.me/`, `wa.me/`), карта Яндекса как facade-картинка со ссылкой, форма.
- **Privacy** — политика обработки персональных данных. Обязательна: на неё ссылается чекбокс согласия в форме.
- **404** — ссылки на разделы, 3 случайных кейса.

## 8. SEO

### 8.1 Мета-теги

На каждой странице: `<title>` до 60 символов, `<meta name="description">` до 160, `<link rel="canonical">`, `og:title`, `og:description`, `og:image` (1200×630), `og:url`, `og:type`, `og:locale=ru_RU`, `og:site_name`, `twitter:card=summary_large_image`, `<html lang="ru">`.

Источник — блок `seo` в JSON. При его отсутствии значения генерируются из `title` + `summary` по шаблону из `site.json`. Отсутствие `og:image` — ошибка сборки.

### 8.2 Заголовки

Ровно один `<h1>` на страницу. `<h2>` — секции, `<h3>` — подсекции. Уровни не пропускаются. Визуальный размер задаётся классом, а не выбором тега.

### 8.3 Микроразметка JSON-LD

| Страница | Схемы |
|---|---|
| Все | `Organization`, `WebSite`, `BreadcrumbList` |
| Услуга | `Service` + `offers` с `priceCurrency: "RUB"` |
| Кейс | `CreativeWork` + `VideoObject` (name, description, thumbnailUrl, uploadDate, duration, embedUrl) |
| Статья | `Article` |
| Главная и страницы услуг | `FAQPage` |
| Контакты | `LocalBusiness` |

Генерируется в `scripts/lib/seo.js`.

### 8.4 Техническое

`sitemap.xml` генерируется из JSON, `lastmod` — из даты изменения. `robots.txt` с указанием sitemap и `Clean-param` для utm-меток.

`.htaccess`: 301-редиректы (`www` → без `www`, `http` → `https`, без слэша → со слэшем), gzip/brotli, кеш-заголовки для статики (1 год для файлов с хешем в имени), `X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`.

Изображения: `<picture>` с AVIF → WebP → JPG, обязательные `width`/`height` (защита от CLS), `loading="lazy"` для всего кроме hero, осмысленный `alt` из JSON.

## 9. Аналитика

- **Яндекс.Метрика** — основная: вебвизор, карта скроллинга, цели.
- **GA4** — опционально, включается наличием `analytics.ga4Id` в `site.json`.
- Оба счётчика грузятся отложенно: `requestIdleCallback` или первое взаимодействие пользователя. Синхронная загрузка в `<head>` запрещена — она убивает LCP.
- Единая обёртка `analytics.js` с `track(event, params)`, отправляющая событие в оба счётчика. В коде компонентов вызывается только `track()`.

**События:** `form_view`, `form_start`, `form_submit`, `form_success`, `form_error`, `click_phone`, `click_telegram`, `click_whatsapp`, `click_email`, `play_showreel`, `play_case_video`, `open_case`, `filter_works`, `scroll_50`, `scroll_90`.

Cookie-баннер и страница `/privacy/` — требование 152-ФЗ при сборе персональных данных через форму.

## 10. Форма заявки и бэкенд

### 10.1 `public/api/lead.php`

Порядок обработки; каждый шаг обязателен:

1. Только `POST` с `Content-Type: application/json`. Иначе 405.
2. Проверка `Origin`/`Referer` против списка доменов из конфига.
3. **Honeypot** — скрытое поле заполнено: вернуть `{ok:true}` (не давать боту сигнал) и молча выйти.
4. **Временная метка** — форма отправлена быстрее чем через 3 секунды после рендера: считать ботом.
5. **Rate limit** — файловый счётчик по хешу IP: 5 заявок за 10 минут, иначе 429.
6. **Валидация** — `name` 2–80 символов; `contact` — email, телефон или `@username`; `message` до 2000; `service` только из известных слагов; `consent === true` обязателен. Ошибки возвращаются по каждому полю отдельно: `{ok:false, errors:{field:"текст"}}`.
7. **Санитизация** — `strip_tags`, нормализация переносов, экранирование под HTML-разметку Telegram.
8. **Telegram** — Bot API `sendMessage`, `parse_mode=HTML`, чат из конфига, timeout 5 секунд.
9. **Email** — SMTP хостинга. PHPMailer кладётся в `api/lib/` вендором, без Composer; либо `mail()` с корректными заголовками, если хостинг это позволяет. Решение фиксируется на этапе 7 после проверки хостинга.
10. **Резервная запись** — всегда дописывать в `storage/leads.csv` вне webroot. Telegram и SMTP падают; заявка не должна теряться.
11. **CRM-хук** — если в конфиге задан `CRM_WEBHOOK_URL`, отправить туда тот же JSON через POST. Задел под amoCRM/Bitrix24 без переписывания эндпоинта.
12. Ответ `{ok:true}`. Детали ошибок наружу не отдаются — только в лог.

**Секреты** (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, доступы SMTP, `CRM_WEBHOOK_URL`) — в `api/config.php`, который в `.gitignore` и закрыт правилом `.htaccess`. В репозитории лежит `config.sample.php`. Токен бота никогда не попадает в клиентский код.

### 10.2 Клиент (`form.js`)

`fetch` с `AbortController` и timeout 15 секунд. Кнопка блокируется на время отправки и показывает спиннер. Успех — состояние «Заявка отправлена, свяжемся в течение дня» + `track('form_success')`. Ошибка сети — сообщение с прямой ссылкой на Telegram как запасной канал.

Валидация на клиенте дублирует серверную, но не заменяет её.

## 11. Производительность и доступность

**Цели:** Lighthouse Performance ≥90 (mobile), Accessibility ≥95, Best Practices ≥95, SEO 100. LCP < 2.5s, CLS < 0.1, INP < 200ms. HTML страницы < 100 КБ, CSS < 60 КБ, JS < 40 КБ (без сжатия).

**Как достигаем:** критический CSS инлайном в `<head>`, остальной отложенно; JS-модули с `defer`; шрифты preload + `swap`; видео `preload="none"` кроме hero; изображения AVIF/WebP с заданными размерами; embed-плееры только через facade; счётчики аналитики отложенно.

**Доступность:** контраст ≥4.5:1 для текста и ≥3:1 для интерактивных элементов; `:focus-visible` — лаймовое кольцо 2px с отступом 2px; полная навигация с клавиатуры; skip-link к `<main>`; `aria-expanded` на бургере и аккордеонах; `aria-live` для результата формы; фокус-ловушки в мобильном меню и лайтбоксе; семантические `<nav>`, `<main>`, `<article>`, `<section aria-label>`; тач-цели ≥44×44px.

**Браузеры:** последние 2 версии Chrome, Firefox, Safari, Edge; iOS Safari 15+; Android Chrome. IE не поддерживается.

## 13. Верификация

После каждого этапа:

```
npm run validate    # контент валиден
npm run build       # сборка без ошибок
npm run preview     # визуальная проверка
```

### Сквозные сценарии проверки требований ТЗ

1. **Масштабируемость (ключевая проверка).** Добавить в `works.json` новый объект и в `services.json` пятую услугу с заглушками медиа → `npm run build` → страницы `/works/<новый>/` и `/services/<новая>/` существуют, карточки появились в списках и на главной, обе записи есть в `sitemap.xml`. Ни один HTML-шаблон при этом не менялся.
2. **Устойчивость контента.** Удалить обязательное поле у кейса → `npm run validate` падает с сообщением, называющим файл, индекс объекта и поле.
3. **SEO.** Прогнать 3 страницы разных типов через валидатор микроразметки Яндекса и Google Rich Results — ошибок нет. Проверить `og:image` через отладчик ссылок VK и превью в Telegram. Убедиться, что на каждой странице ровно один `h1`.
4. **Форма.** Отправить тестовую заявку на реальном хостинге → сообщение в Telegram, письмо на email, строка в `leads.csv`. Отправить 6 заявок подряд → шестая отклонена (429). Заполнить honeypot → ответ `{ok:true}`, но в Telegram ничего не пришло. Отправить без `consent` → ошибка валидации.
5. **Аналитика.** В отчёте Метрики видны цели `form_success`, `play_showreel`, `click_telegram`.
6. **Производительность.** Lighthouse (mobile, с троттлингом) на главной, странице услуги и кейсе → Performance ≥90, Accessibility ≥95, SEO 100.
7. **Доступность.** Пройти главную и форму только с клавиатуры: фокус всегда виден, из мобильного меню и лайтбокса выход по Escape. Включить `prefers-reduced-motion` — анимации отключены.
8. **Адаптив.** Проверить на 360, 768, 1024, 1440, 1920 — горизонтального скролла нет ни на одной ширине.
