# Выкладка на хостинг

Рассчитано на обычный шаред-хостинг с Apache и PHP 8.1+ (Beget, Timeweb, Reg.ru).

---

## 1. Подготовка перед заливкой

Сборки в проекте нет: правки вносятся прямо в файлы. Все замены ниже — обычный поиск с заменой по всем HTML.

### Домен

Сейчас везде стоит плейсхолдер `https://keyframe.example`. От него зависят `canonical`, `og:url` и все ссылки в `sitemap.xml`. Оставить его — значит отдать поисковикам карту чужого сайта.

Найти все вхождения:

```bash
grep -rl "keyframe.example" --include=*.html --include=*.xml .
```

Заменить на боевой домен во всех найденных файлах, включая `sitemap.xml`.

### Реквизиты и политика

`privacy/index.html`: название юрлица, ИНН, адрес. Текст политики написан по смыслу 152-ФЗ, но **не проверен юристом** — перед публикацией показать. В конце страницы стоит явная врезка об этом; её нужно удалить после замены реквизитов.

Название юрлица дублируется в подвале каждой страницы — проверить грепом.

### Аналитика

В теге `<body>` на каждой странице:

```html
<body data-analytics="on" data-metrika="12345678" data-ga4="">
```

Пока `data-analytics="off"`, счётчики не грузятся и cookie-баннер не показывается. Атрибут есть на всех 22 страницах — менять везде.

## 2. Заливка

```
public_html/          ← сюда всё содержимое папки проекта
  index.html
  assets/
  media/
  fonts/
  api/
  .htaccess
storage/              ← создать РЯДОМ с public_html, не внутри
```

Файлы `README.md`, `CLAUDE.md`, папку `docs/` и «Посмотреть сайт.command» заливать не нужно — они для работы, а не для посетителей.

`storage/` обязан лежать **вне** webroot: в нём резервная копия заявок с персональными данными. Путь по умолчанию в `config.php` — `__DIR__ . '/../../../storage'`, то есть на уровень выше `public_html`. Если структура хостинга другая, поправить путь.

Права: `storage/` — 700, файлы сайта — 644, каталоги — 755.

## 3. Настройка формы

```bash
cp api/config.sample.php api/config.php
```

Заполнить:

| Поле | Где взять |
|---|---|
| `allowed_origins` | Боевые домены. Localhost из списка убрать. |
| `telegram.token` | @BotFather → `/newbot` |
| `telegram.chat_id` | @userinfobot. Для группы значение отрицательное, бота нужно в неё добавить и дать право писать. |
| `mail.*` | Панель хостинга, раздел почты. SMTP надёжнее `mail()`: письма без аутентификации чаще уходят в спам. |
| `crm_webhook` | Пусто, пока CRM нет. |

Проверить, что `config.php` закрыт:

```bash
curl -I https://ваш-домен/api/config.php
```

Ожидается `403`. Если пришло `200` — правило в `.htaccess` не сработало, форму включать нельзя.

## 4. Боевая проверка бэкенда

**Это главный пункт всей инструкции.** Логика `lead.php` никогда не запускалась: PHP на машине разработки не был установлен, локально проверялся только фронтенд формы на Node-моке. Прогнать сценарии ниже нужно сразу после заливки.

| № | Что делаем | Ожидаем |
|---|---|---|
| 1 | Отправляем заявку с сайта | Сообщение в Telegram, письмо на почту, строка в `storage/leads.csv` |
| 2 | Шесть заявок подряд | Шестая: `429` и текст про десять минут |
| 3 | В devtools заполняем скрытое поле `company` и отправляем | Ответ `{"ok":true}`, но в Telegram ничего не пришло |
| 4 | Снимаем галочку согласия через devtools, отправляем | `422` и ошибка по полю `consent` |
| 5 | `curl -X POST https://домен/api/lead.php` без заголовка Origin | `403` |
| 6 | Открываем `https://домен/api/lead.php` в браузере | `405` |
| 7 | Временно ломаем токен Telegram, отправляем заявку | Заявка всё равно в `storage/leads.csv` |

Сценарий 7 — самый важный: он проверяет, что заявки не теряются, когда внешний сервис недоступен.

Если что-то не сходится, смотреть лог ошибок PHP в панели хостинга. Наружу `lead.php` детали не отдаёт намеренно — всё в `error_log`.

## Обновление контента

Правки вносятся прямо в файлы — как это делать, описано в [how-to-edit.md](how-to-edit.md).

Дальше залить изменённые файлы поверх. **`api/config.php` и `storage/` не трогать**: первый содержит секреты, второй — сохранённые заявки. В репозитории их нет, поэтому при заливке всей папки они не перезапишутся, но при синхронизации через FTP-клиент их стоит внести в исключения.

После заливки открыть изменённые страницы и проверить, что всё на месте. Если правился сквозной элемент — шапка, подвал, форма — проверить несколько страниц из разных разделов.
