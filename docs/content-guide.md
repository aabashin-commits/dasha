# Как добавлять контент

Весь контент сайта лежит в каталоге `content/` в файлах JSON. Вёрстку править не нужно: страницы, мета-теги и записи в карте сайта создаются сами.

После любой правки:

```bash
npm run build
```

Если что-то заполнено неверно, сборка остановится и скажет, в каком файле, в каком по счёту объекте и в каком поле проблема. Это нормально — так и задумано.

---

## Правила, общие для всех файлов

**Слаг** — это адрес страницы. Только латинские буквы, цифры и дефисы: `doroga-v-teriberku`. Слаг должен быть уникальным и после публикации **не меняться** — иначе ссылка перестанет работать и страница потеряет позиции в поиске.

**Кавычки** внутри текста — «ёлочки». Прямые кавычки `"` внутри строки сломают JSON.

**Тире** — длинное `—`, а не дефис.

**Запятая** после последнего элемента списка недопустима. Это самая частая причина ошибки «сломанный JSON».

## Добавить работу в портфолио

### 1. Положить изображения

```
public/media/works/имя-работы/
  poster.jpg     обложка
  01.jpg         кадры для галереи, если есть
  02.jpg
```

Обложка снимается в пропорции формата: вертикальный ролик — вертикальная обложка. Ширина 1600 пикселей достаточна.

Затем сгенерировать версии WebP:

```bash
npm run images
```

### 2. Добавить запись в `content/works.json`

Новый объект в конец списка:

```json
{
  "slug": "имя-работы",
  "title": "Название",
  "service": "documentary",
  "client": "Название заказчика",
  "year": 2026,
  "location": "Москва",
  "ratio": "16:9",
  "featured": true,
  "order": 7,
  "summary": "Одно-два предложения для карточки",
  "description": "Развёрнутый рассказ для страницы кейса",
  "poster": "/media/works/имя-работы/poster.jpg",
  "video": { "provider": "vk", "id": "video-123456_789", "duration": "PT4M12S" },
  "gallery": [
    { "src": "/media/works/имя-работы/01.jpg", "alt": "Что на кадре" }
  ],
  "credits": [{ "role": "Оператор", "name": "Имя" }],
  "results": [{ "label": "Просмотров", "value": "1,2 млн" }],
  "tags": ["документальное"],
  "seo": {
    "title": "Название — что это",
    "description": "Описание для поисковой выдачи"
  }
}
```

### Что означают поля

| Поле | Пояснение |
|---|---|
| `service` | Слаг направления из `services.json`. Несуществующее значение остановит сборку. |
| `ratio` | `9:16`, `16:9`, `2.39:1`, `1.66:1`, `4:3` или `1:1`. От него зависит форма карточки в сетке. |
| `featured` | `true` — работа попадает на главную. Туда выводятся первые шесть по `order`. |
| `order` | Порядок вывода. Меньше — выше. |
| `video` | Можно не указывать: тогда на странице будет обложка без плеера. |
| `gallery` | Можно не указывать: секция кадров просто не появится. |
| `alt` | Описание изображения для незрячих и для поиска. **Обязательно.** Описывать, что в кадре, а не «фото 1». |
| `seo.title` | До 60 символов. Это заголовок в результатах поиска. |
| `seo.description` | До 160 символов. Это текст под заголовком в выдаче. |

### Где взять `video.id`

**VK Video.** В адресе ролика `vk.com/video-227821695_456239019` идентификатор — это `video-227821695_456239019` целиком.

**Rutube.** В адресе `rutube.ru/video/abc123def456/` идентификатор — `abc123def456`.

`duration` — длительность в формате `PT` + минуты + `M` + секунды + `S`. Четыре минуты двенадцать секунд — это `PT4M12S`. Поле нужно для поисковиков: с ним ролик может попасть в видеовыдачу.

## Добавить направление

Новый объект в `content/services.json`. Появится карточка на главной, на странице направлений, отдельная страница и пункт в выпадающем списке формы.

Ключевые поля:

- `format` — `{ "ratio": "16:9", "duration": "3–5 мин" }`. Из соотношения рисуется значок формата на карточке.
- `priceFrom` — число без пробелов и знака рубля: `120000`. Если поле не указывать, вместо цены покажется текст из `priceNote` — так сделано у документального кино.
- `order` — порядок вывода.

## Добавить статью в журнал

Обложка — в `public/media/journal/слаг-статьи/cover.jpg`, затем `npm run images`.

Запись в `content/journal.json`. Текст статьи — в поле `body`, с упрощённой разметкой:

| Как написать | Что получится |
|---|---|
| `## Заголовок` | Подзаголовок раздела |
| `### Заголовок` | Подзаголовок помельче |
| Пустая строка между абзацами | Новый абзац |
| `- пункт` | Пункт списка |
| `**важное**` | Выделение |
| `[текст](/адрес)` | Ссылка |
| `> цитата` | Цитата с полосой |

Переносы строк внутри абзаца игнорируются — абзацы разделяются пустой строкой. В JSON перенос записывается как `\n`, а пустая строка между абзацами — как `\n\n`.

Всё, что не входит в таблицу, останется обычным текстом.

## Поменять контакты, меню или тексты формы

`content/site.json`. Оттуда берутся телефон, почта, Telegram, адрес, пункты меню в шапке и подвале, реквизиты в политике и текст, который человек видит после отправки заявки.

---

## Что нельзя менять без разработчика

- **Названия полей** в JSON. Переименование поля равносильно его удалению.
- **Слаг уже опубликованной страницы.** Ссылка сломается.
- **Структуру каталогов** в `public/media/`.
- **Файлы в `src/`.** Это вёрстка и логика, а не контент.

---

## Если сборка ругается

Сообщение всегда называет файл, номер объекта и поле. Нумерация начинается с нуля: `works.json[3]` — четвёртая работа в списке.

| Сообщение | Что делать |
|---|---|
| `сломанный JSON` | Лишняя или пропущенная запятая, прямая кавычка внутри текста |
| `нет обязательного поля «X»` | Добавить поле |
| `файла нет на диске` | Проверить путь и запустить `npm run images` |
| `слаг «X» уже занят` | Две записи с одинаковым слагом |
| `service «X» не найден` | Опечатка в слаге направления |
| `seo.title длиннее 60 символов` | Сократить |
| `нет «alt»` | Описать, что на изображении |
