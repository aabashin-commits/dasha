## Установка

Нужен Node.js 20 или новее.

```bash
npm install
npm run images   # генерация изображений-заглушек
npm run build
npm run preview  # http://127.0.0.1:4321
```

Шрифты уже лежат в `public/fonts` и закоммичены. Перекачивать их нужно, только если меняется состав гарнитур: `node scripts/fetch-fonts.js`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Сервер на :4321 с пересборкой при изменении файлов |
| `npm run build` | Валидация → ассеты → страницы → sitemap → `dist/` |
| `npm run validate` | Только проверка `content/*.json` |
| `npm run preview` | Просмотр собранного `dist/` без пересборки |
| `npm run images` | Изображения-заглушки из `content/*.json` |
| `npm run mock` | Сервер на :4322 с моком эндпоинта заявок |

## Как это устроено

```
content/*.json  →  scripts/build.js  →  dist/
                         ↑
                   src/templates/
```

`content/` — единственный источник контента. Билд-скрипт читает JSON, рендерит шаблоны и пишет статические HTML со всеми мета-тегами, микроразметкой и записями в `sitemap.xml`.

Добавление кейса — это добавление объекта в `content/works.json`. Ни один шаблон при этом не меняется.

Перед каждой сборкой запускается `validate-content.js`. Он падает с внятной ошибкой, если в JSON пропущено обязательное поле, слаг не уникален, файл медиа отсутствует на диске или `seo.title` длиннее шестидесяти символов. Это защита от того, чтобы опечатка в контенте уехала на прод молча.

### Стек

HTML, CSS и vanilla JS. Node.js только на сборке, PHP только в обработчике формы. Никаких фреймворков и никаких runtime-зависимостей в браузере.

Dev-зависимостей три: `esbuild` (бандл и минификация), `sharp` (изображения), `chokidar` (watch).

## Структура

```
content/        JSON — весь контент сайта
src/
  templates/    шаблоны страниц и переиспользуемые части
  styles/       токены, база, по файлу на компонент
  scripts/      ES-модули, каждый со своим init()
public/         копируется в dist как есть
  api/          обработчик формы на PHP
scripts/        сборка, валидация, генераторы
dist/           результат сборки (в .gitignore)
```

## Что нужно сделать перед публикацией

Сейчас в проекте заглушки. Перед выкладкой требуется:

1. **Домен** — заменить `url` в `content/site.json`. От него зависят `canonical`, `sitemap.xml` и `og:url`.
2. **Реквизиты юрлица** — `legalName` и `inn` в `site.json`; текст политики на `/privacy/` показать юристу.
3. **Telegram и почта** — скопировать `public/api/config.sample.php` в `config.php` и заполнить.
4. **Яндекс.Метрика** — вписать ID в `site.json` и переключить `analytics.enabled` в `true`.
5. **Реальный контент** — тексты, фото и видео вместо заглушек.

Подробности каждого пункта — в [docs/deploy.md](docs/deploy.md).

## Известные ограничения

**Логика `public/api/lead.php` не прогонялась.** PHP на машине разработки не установлен, поэтому проверить эндпоинт локально было нельзя. Фронтенд формы полностью проверен на Node-моке (`npm run mock`), повторяющем контракт: те же коды ответов, та же форма ошибок по полям, та же логика ханипота и лимита частоты.

Сам PHP нужно прогнать на хостинге по сценарию из [docs/deploy.md](docs/deploy.md) — это первое, что стоит сделать после заливки.
